# Known limitations and another week

The implementation prioritizes seven-page provenance, conservative answers and explicit failure handling. It uses a small lexical retriever and two bounded LLM calls: standalone English query/intent resolution, then evidence-grounded generation. Multilingual questions use the same English source snapshot. The app retains section and table context and checks source identifiers, quoted passages and numbers before displaying a factual answer. Those checks reduce hallucinations; they cannot prove a paraphrase is fully supported or catch every incorrect association between a treatment and a source. Intent classification also remains model-dependent.

The source website includes medical marketing, inconsistent scopes and potentially ambiguous or changing prices. The assistant attributes information to those pages, distinguishes program duration from recovery and declines personal medical suitability questions. It does not establish clinical efficacy, diagnose, book appointments or replace a treating physician. Video titles are available, but videos are not transcribed. Lexical retrieval can miss paraphrases, especially when query translation is imperfect. English, Portuguese, Spanish and Arabic are the supported response languages; other languages fall back to English.

The deployment is intended for a low-volume assessment. Shared quotas are bounded and other usage of the same Groq organization can exhaust available capacity. The site remains accessible when the model is unavailable, but answers require a working provider. Refresh depends on robots permissions, page selectors and scheduled GitHub Actions; a failed refresh preserves the previous snapshot and its original collection time. A scheduled probe checks service availability without making a model call, and is not an uptime guarantee.

Lead capture is deliberately an honest demonstration: it records consented interest in a private database but sends no notification to PlacidWay. Operational logs retain only minimal metadata and redacted unanswered questions for 30 days. Basic redaction cannot reliably remove every personal detail; no sensitive patient data should be submitted. Automatic deletion affects live application tables, while managed backups and providers may retain information under their own policies.

With another week, I would expand the multilingual/adversarial evaluation set, measure retrieval recall against labeled evidence and compare lexical search with multilingual embeddings before adding infrastructure. I would add stronger claim-to-evidence evaluation, price/entity-specific checks and source-conflict fixtures; instrument quota headroom and stale-source alerts; and review the system with qualified medical and privacy stakeholders. For an actual deployment, I would integrate an authorized quote destination with verified delivery, define retention and deletion procedures across backups/providers, and add stronger abuse protection if traffic justifies it.
